# WebDev Coursework Platform

A coursework portfolio and learning application built around Santa Monica
College classes. The React frontend presents course modules, assignments,
practice assessments, a code playground, projects, and personal accounts. The
NestJS API serves quiz data and progress, account workflows, and presentation
visit reports.

[Open the site](https://webdev-coursework.com) ·
[Browse the documentation](docs/README.md) ·
[Read the architecture](docs/architecture.md)

## What runs here

| Part       | Responsibility                                                                                         | Source                                                                                                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Frontend   | Routes, course content, practice assessments, account screens                                          | [`frontend/src/routes/AppRoutes.tsx`](frontend/src/routes/AppRoutes.tsx), [`frontend/src/courses/`](frontend/src/courses/), [`frontend/src/features/`](frontend/src/features/) |
| API        | Quiz and progress endpoints, account access, analytics, request protection                             | [`backend/src/app.module.ts`](backend/src/app.module.ts)                                                                                                                       |
| PostgreSQL | Quiz records, client-ID progress, accounts, sessions, mail outbox, analytics, and shared request state | [`backend/src/db/`](backend/src/db/), [`backend/src/accounts/store/`](backend/src/accounts/store/)                                                                             |

The browser stores a client ID in `localStorage` for coursework progress. The
current active course configuration uses the same `clientId` storage key for
every course. That ID is separate from an account session: signing in does not
synchronize coursework progress across devices. Shared client practice
assessments keep their answer keys in the browser; they are not protected graded
exams. See the [architecture](docs/architecture.md) and
[assessment standard](docs/quiz-assessment-standard.md) for these boundaries.

Course material currently includes CS 56, CS 60, CS 70, CS 79A, CS 79C, CS 79D,
CS 80, CS 81, CS 85, CS 87A, and ESL 10G. The
[course catalog](frontend/src/courses/catalog/README.md) identifies course IDs
and active app content; individual course directories own their assignments.

## Local development

The commands below are defined in the root and workspace `package.json` files.
Use Node.js **24.15.0** (`.nvmrc`), the repository-pinned Yarn **4.14.1**
(`.yarnrc.yml`), and Docker Compose for the dedicated local PostgreSQL service.

```sh
git clone https://github.com/sergehall/webdev-coursework.git
cd webdev-coursework
nvm use
corepack enable
corepack prepare yarn@4.14.1 --activate
yarn runtime:check
yarn install:strict
```

Create `frontend/.env.local` with browser-visible development settings:

```dotenv
VITE_ENVIRONMENT=development
VITE_API_URL=
VITE_OWNER_API_URL=
```

Empty API URLs use Vite's local proxy to `http://localhost:5050`. Set
`VITE_QR_ANALYTICS_ENABLED=true` only when testing marked presentation-link
collection. `VITE_` values are public in the browser bundle. Keep signing keys
in backend configuration only.

For the API, copy the committed template and replace placeholder secrets:

```sh
cp backend/.env.example backend/.env
yarn workspace backend owner:configure:local
docker compose --env-file backend/.env.local -f compose.local.yml up -d --wait
yarn workspace backend migration:run:local
yarn dev
```

The helper creates ignored `backend/.env.local`, configures PostgreSQL on
`127.0.0.1:55432`, and generates missing local account keys. Development loads
`.env.local` before `.env`. Check `backend/.env` for quiz signing and admin API
settings; use distinct non-placeholder values. The helper defaults account
access to disabled until its GitHub client secret is supplied; for
password-only use, clear all four GitHub settings before enabling accounts.
Account email and OAuth flows also need their own server-side settings. See
[accounts and analytics](docs/owner-account-analytics.md) for activation
requirements. The default account origin generated by the helper is
`http://127.0.0.1:3000`; use that address for account testing.

| Local endpoint | Address                        |
| -------------- | ------------------------------ |
| Frontend       | `http://127.0.0.1:3000`        |
| API            | `http://localhost:5050`        |
| API health     | `http://localhost:5050/health` |

`yarn dev:frontend` and `yarn dev:backend` start the processes separately.
`yarn stop:dev` stops the processes on ports 3000 and 5050 and the local
PostgreSQL container; the database volume is retained. Restart the container
with the Compose command above.

## Checks and builds

```sh
yarn check:frontend
yarn check:backend
yarn test:frontend
yarn test:backend
yarn build
```

`check:frontend` runs TypeScript and ESLint. `check:backend` also checks
migration layout. `test:backend` runs Jest unit and end-to-end suites; account
HTTP integration tests require the separate disposable PostgreSQL environment
described in the [account guide](docs/owner-account-analytics.md). `build`
builds both workspaces. See each workspace's `package.json` for narrower
commands.

## Documentation and deployment

Start with the [documentation index](docs/README.md) to find the architecture,
API, accounts, migrations, assessment, security, and operations guides. The
runtime OpenAPI document is the API contract when Swagger is enabled; access
rules are in the [API guide](docs/api-contract-and-security.md).

The repository contains a Vercel frontend configuration
([`frontend/vercel.json`](frontend/vercel.json)) and a Heroku backend release
hook ([`Procfile`](Procfile)). The account-only release hook applies its
explicit migration allowlist before the web process starts. GitHub Actions run
frontend checks on `main` pushes and pull requests; the production build
workflow is manual. Repository configuration and dated rollout notes do not by
themselves establish the current live deployment state.

This is an educational portfolio. Course-specific instructions and source
attribution live with the course materials.
